# k3-bom-skill

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/)

[![Version](https://img.shields.io/badge/version-1.0.0-green.svg)](CHANGELOG.md)

金蝶 K3「BOM单 - 新增 / 修改」明细表批量录入技能包 —— 一套给 AI Agent 与 RPA 用的**可复现**流程。

把「物料代码 + 用量」两列静默写进 K3 的 `SPR32A70` 明细表格；其余列（商品名称、规格型号、商品属性、单位、子项类型、使用状态、发料仓库/仓位）由 K3 在提交代码后自动带出。**全程不点保存**，录完由人核对后自己保存。

```
Excel 汇总表  ──►  data.json  ──►  K3 明细表（只填两列）
                                    ├─ 商品名称 / 规格型号：K3 自动带出
                                    ├─ 单位 / 子项类型 / 使用状态：K3 自动带出
                                    └─ 发料仓库 / 仓位：K3 自动带出
```

## 特性

- ✅ **36 行 BOM 实测一次录入通过**，合计 `77.25` 与源 Excel 完全一致
- ✅ 纯 Windows UI Automation + 屏幕坐标，不依赖 K3 任何接口、不读写数据库
- ✅ 先填完全部代码、再回头统一填用量，两次分页，互不串行
- ✅ 每页填完截图确认后才滚动，配合合计值终检
- ✅ 附循环自检器（10 个用例），可验证流程可重复性
- ⚠️ 坐标强绑定分辨率 / DPI / 列宽，换机器必须重新标定（见 [标定](#标定)）
- 🔒 全程本机运行，零网络请求，不采集任何遥测

## 准备数据

仓库**不含任何真实物料数据**。把要录入的内容写成下面任一格式：

`skills/k3-bom-grid-entry/scripts/data.json`

```json
[
  ["1.99.001", "1"],
  ["1.99.002", "0.5"],
  ["1.99.003", "12"]
]
```

或 `data.csv`

```csv
# 物料代码,用量
1.99.001,1
1.99.002,0.5
1.99.003,12
```

加载优先级：环境变量 `K3_DATA` 指向的文件 → `data.json` → `data.csv` → 空（空则脚本报错退出）。加载后自动算出 `TOTAL_EXPECT`（Σ用量）用于终检。

示例文件见 [`data.example.json`](skills/k3-bom-grid-entry/scripts/data.example.json) 与 [`data.example.csv`](skills/k3-bom-grid-entry/scripts/data.example.csv)。

## 使用

```bash
cd skills/k3-bom-grid-entry/scripts

# 1. 打开 K3 的「BOM单 - 新增」单据，露出明细表格，然后 50/50 分屏
python _snap_split.py

# 2. 标定：横滑条归零 → 右拨 1 次 → 读列坐标，写入 _k3_calib.json
python _k3_fill.py calib

# 3. 填代码：第 1~24 行（每页 = 可见行数 - 1）
python _k3_put2.py code 1 24

# 4. 下滚 20 次，视口首行变成序号 25 后，锚定继续填代码
python _k3_fill.py scroll down 20
python _k3_put3.py code 25 36 25 496

# 5. 上滚 30 次回到序号 1，固定用量列焦点后分页填用量
python _k3_fill.py scroll up 30
python _k3_qty.py qty 1 24 1 496
python _k3_fill.py scroll down 20
python _k3_qty.py qty 25 36 25 496

# 6. 截图核对 + 合计校验（脚本会打印视口合计，与 TOTAL_EXPECT 对比）
```

**最后一步永远是：核对无误后由人自己点保存。这些脚本从头到尾不会点击保存按钮。**

完整分页时序见 [`examples/bom-36rows.md`](examples/bom-36rows.md)。

## 标定

列坐标随分辨率、DPI 缩放、K3 列宽而变化，**不要抄别人机器上的数字**。

```bash
python _k3_fill.py calib
```

会依次做：横滑条归零 → 右拨 1 次 → 用 UIA 读 `商品代码`/`用量` 两列的 `rect.left` → 写 `_k3_calib.json`。当前验证过的布局（1920×1032，左窗口 960 / K3 右 960，横拨 1 次）：

| 目标 | 坐标 |
|---|---|
| 首行 y | 496 |
| 行距 | 16 px |
| 可见行数 / 每页行数 | 25 / 24 |
| 商品代码列 | x = 1090（`CODE_LEFT=1043`） |
| 用量列 | x = **1400**（`QTY_LEFT=1392`）⚠️ 不是 1740/1770/1800 |
| 横向右箭头 / 左箭头 | `(1891, 908)` / `(987, 908)` |
| 纵向下滚 / 上滚 | `(1908, 891)` / `(1908, 468)` |

## 核心结论（先读这三条，能省 12 轮试错）

| 错误做法 | 真实后果 | 正确做法 |
|---|---|---|
| 每格先发 `ESC` 退编辑态 | ESC = **取消该格输入**，已写内容清空 | 永不发 ESC；退编辑态点列标题空白 `(1890, 476)` |
| 用 `focused()` 读回校验 | 无弹窗时读的是 UIA **陈旧缓存**，误报失败或误报命中 | 靠**每页截图 + 全表合计**校验 |
| 滚动条坐标写死 | 落点常在条外，箭头从未点中，视口永远不动 | 横 y=**908**、下滚 `(1908,891)`、上滚 `(1908,468)`，从 UIA 动态读 |

外加一条：把 `1740~1800` 当用量列会写进「备注」列，`1830~1860` 是「损耗率」。**横拨一次后用量列在 x≈1400。**

## 单格动作序列

一格一个循环，绝不链式连续输入：

```
click(x, y) → ctrl+a → DELETE → 输入内容 → ENTER → 关掉可能出现的模态框
```

提交代码后 K3 会让视口自动上滚 16 px，所以**每写完一页必须重新读当前视口首行序号**再继续。

## 常见问题

**Q：脚本跑完弹「代码在数据库中不存在或被禁用」？**
A：物料代码被停用，或前一次输入没有提交、K3 把新旧内容**拼接**了。关掉弹窗，`ctrl+a` → DELETE 后重录该格。

**Q：明细里某行串到上一行了？**
A：ENTER 提交后视口自滚了 16 px 没被发现。重新读当前视口首行序号，重算 y。

**Q：怎么看「用量」列？**
A：点一次横向右箭头 `(1891, 908)`；再截一次图确认列标题出现「用量」。

更多见 [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md)。

## 安全与隐私

- **零网络**：全部脚本只用 `ctypes` / `pywinauto` / `win32gui` / `json` / `csv`，没有任何 HTTP / socket 调用，不上报、不下载、无遥测、无回连。
- **不写日志**：输出只到终端，避免物料清单被意外落盘。
- **仓库无真实数据**：物料编码、BOM 单号、路径、合计值全部为合成占位。
- **本地文件**：只写 `scripts/_k3_calib.json`（本机坐标）与 `__pycache__/`，两者都在 `.gitignore` 里。

细节与自查命令见 [SECURITY.md](SECURITY.md)。

## 免责与边界

> 本项目是**键盘鼠标层面的 UI 自动化脚本**，不是金蝶的插件、补丁或官方工具。请在使用前完整阅读本节。

### 一、不做的事

- 不绕过任何权限校验、不注入进程、不读写 K3 数据库、不调用任何 K3 内部接口或隐藏 API。
- 不修改 K3 的程序文件、不 hook、不打补丁。
- **不点击「保存」**。所有脚本执行完毕时，单据仍处于"未保存"状态，是否保存、何时保存，完全由人决定。

### 二、你需要自己承担的事

1. **业务正确性**：脚本只负责"把这两列字符串敲进格子"。物料是否选对、用量是否符合工艺、替代料/损耗率/生效日期等业务字段是否合理，全部由使用者负责。脚本不会、也无法判断一个 BOM 是否正确。
2. **结果核对**：脚本提供的是"视口合计 vs `TOTAL_EXPECT`"的机械比对，它只能发现**数量层面的偏差**，发现不了"第 5 行和第 9 行物料写反了但合计恰好相同"这类错误。**最终必须逐行人工核对**，或导出后与源表做 diff。
3. **生产环境风险**：请务必先在**测试账套**跑通全流程，确认账套、期间、BOM 版本、默认仓库/仓位都正确，再考虑用于生产单据。
4. **提交前复核**：录完不保存是设计上的安全边界。请在保存前确认单据头（BOM 编号、父项物料、版本号、数量）也没有被误改。

### 三、UI 自动化的固有风险

- **坐标漂移**：脚本按像素坐标点击。改变窗口大小、移动分屏比例、拖动列宽、切换 DPI 缩放、改系统字体大小、换分辨率、Windows 主题/高对比度模式，都可能让所有坐标失效，**并且失效时往往不会报错，只是把数据写进了错误的格子**。因此每次运行前都要重新标定并截图确认列位置。
- **时序不确定**：K3 是 VB6 单体应用，提交一格代码后可能触发数据库查询、自动带出、模态提示框。机器慢、账套大、网络数据库延迟高时，固定 `sleep` 可能不够，出现"弹出提示框但脚本继续点"的情况。脚本内置了弹窗探测，但**不能保证 100% 捕获所有弹窗**。
- **焦点被抢**：任何其他程序弹窗、系统通知、输入法候选框、远程桌面重连，都可能夺走焦点，使按键落到别处。运行时请勿操作鼠标键盘，关闭通知与屏保。
- **不可撤销**：一旦点了保存，K3 侧就是真实数据。UI 自动化没有事务回滚。

### 四、兼容性

- 仅在 **金蝶 K3（老版 VB6 界面，`SPR32A70` 表格控件，窗口类 `ThunderRT6FormDC`）** 上验证过。
- **未**验证：K3 Cloud / 金蝶云星空 / KIS / 其他版本的 BOM 界面。这些产品是全新的前端架构，本项目的坐标法与控件假设**全部不适用**。
- 不同 K3 补丁包、不同自定义字段、不同单据模板，列顺序会变，需要重新标定。
- 不同 Windows 语言版本下 K3 标题可能出现乱码，这是 K3 本身的编码问题，脚本已改为按窗口类名匹配以规避。

### 五、数据与隐私

- 所有脚本**只在本机运行，不发起任何网络请求**，不上传、不下载、不埋点、不收集遥测。
- 仓库内**不含任何真实物料编码、真实 BOM 单号、真实公司名、真实路径**。`data.example.json` / `data.example.csv` 全部为合成占位数据。
